# Intent authoring exercise

Read @docs/product-brief.md for the fictional project requirements.
Read @intent.md for the student's proposed implementation instructions.

This round is about writing a useful intent document, not implementing the feature.
Change only intent.md. Help the student reason about scope, constraints and testable
acceptance criteria. Do not silently commit, push, open or merge a PR. The student
opens a PR inside their own fork, targeting that fork's main branch. Opening or
updating the PR starts advisory checks. Only the student's explicit /submit request
submits the selected pushed revision to TensorLearn. Keep the PR open; no merge is
required. Never present an Actions check as a saved official score.
